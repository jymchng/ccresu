33:Tf9b,# Configuration

> One YAML file, validated at startup, with environment variables that always win.

ccresu reads `~/.config/ccresu/config.yaml` by default, or the path given with `--config`. The full annotated example lives in `configs/config.example.yaml`; every field in it is validated, and an invalid value is a startup error rather than a silent fallback.

Resolution order, first match wins: `--config PATH` (or `-c PATH`), then the `CCRESU_CONFIG` environment variable, then the default path. A leading `~` is expanded in all three, and everything derived from the file — such as the API token beside it — follows the file actually in use.

## Environment overrides

Every field can be overridden with a `CCRESU_` prefixed variable: upper-case the section and field, and join nesting with a double underscore. The environment always takes precedence over the file, which keeps secrets out of it.

Environment:

```sh
CCRESU_APP__LOG_LEVEL=debug
CCRESU_RECOVERY__MAX_ATTEMPTS=5
CCRESU_TELEGRAM__BOT_TOKEN=123456:...
CCRESU_SERVER__PORT=8787

ccresu config validate
```

## Sections

| Section | What it controls |
| --- | --- |
| app | Log level and format, and the IANA timezone used for display. |
| claude | Executable name, discovery interval, extra monitored sessions, and the continuation message sent on resume. |
| monitoring | Which detections are on: usage limits distinguish from session completion. |
| detector | Confidence threshold and custom regular expressions for phrasings ccresu does not know yet. |
| scheduler | Poll interval, and the exponential backoff used when a limit message carries no reset time. |
| recovery | Attempt budget, backoff with jitter, startup and verification timeouts, and the concurrency limit. |
| telegram | Bot token, chat id, parse mode and one switch per notification event. |
| server | Loopback host, port, and the browser origins allowed to make read-only requests. |
| storage | SQLite path and busy timeout. |

## Detection patterns

Custom patterns are Go regular expressions matched against normalised text: lower-cased, single-spaced, with curly quotes and dashes folded to ASCII. A rule can require a reset time and carries its own confidence, which is compared with `detector.threshold`.

Teaching ccresu a new phrasing:

```sh
detector:
  threshold: 0.5
  custom_patterns:
    - id: internal-proxy-limit
      kind: five_hour        # five_hour | weekly | other
      pattern: 'proxy quota exhausted'
      confidence: 0.9
      requires_reset: false
      description: our corporate proxy reports the limit differently
```

## Recovery tuning

| Field | Default | Meaning |
| --- | --- | --- |
| max_attempts | 10 | Resume attempts before a session is marked DISCOVERED. |
| initial_delay | 30s | First retry delay after a failed attempt. |
| max_delay | 15m | Ceiling for the exponential backoff. |
| multiplier | 2.0 | Growth factor between attempts. |
| jitter | 0.15 | Random fraction added so retries do not synchronise. |
| startup_timeout | 60s | How long a resume process may take to start producing output. |
| verification_timeout | 120s | How long the verifier waits for the transcript to grow. |
| max_concurrent_recoveries | 3 | Recovery loops allowed to run at once. |

## Showing the effective configuration

Validate, then print:

```sh
ccresu config init          # write the shipped example, mode 0600, never overwriting
ccresu config init --force  # replace an existing file with the shipped example
ccresu config validate      # exits non-zero on the first invalid field
ccresu config show          # effective values after defaults and env overrides
ccresu --json config show   # the same, as JSON
```
