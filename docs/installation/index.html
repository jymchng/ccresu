Installation

Install a released binary with a single line, or build from source with Go 1.26 or newer.

Download .md

Releases are published on the GitHub releases page (https://github.com/jymchng/ccresu/releases). Each tag carries one archive per supported platform plus a checksums.txt with the SHA-256 of every asset, and the installer verifies the checksum before it extracts anything.

Install with one line

Linux and macOS, amd64 or arm64: the installer detects the platform, resolves the newest release, downloads that archive and checksums.txt, verifies the hash, installs the binary into ~/.local/bin and writes ~/.config/ccresu/config.yaml.

Preview it first if you prefer: the dry run prints every action and downloads nothing.

Pin a release by putting the version in the same line. The one on this page is 0.3.0, the newest published release when the page was built.

Install on Windows

The PowerShell installer does the same work in a normal, non-elevated window: it verifies the sha256 of the .zip before extracting it, installs ccresu.exe under %LOCALAPPDATA%, adds that directory to your user PATH and writes %APPDATA%\ccresu\config.yaml.

The installers are short and readable, and you should read what you pipe into a shell: [scripts/install.sh](https://github.com/jymchng/ccresu/blob/main/scripts/install.sh) and [scripts/install.ps1](https://github.com/jymchng/ccresu/blob/main/scripts/install.ps1). Re-running the same line is the supported upgrade path.

Asset naming

Assets are named ccresu_<version>_<os>_<arch>.tar.gz (.zip on Windows), for example ccresu_0.3.0_linux_amd64.tar.gz, ccresu_0.3.0_darwin_arm64.tar.gz and ccresu_0.3.0_windows_amd64.zip. Supported targets: linux and darwin on amd64 and arm64, windows on amd64 and arm64. The installers pick the matching one for the machine they run on.

Build from source

First run

  1. Create ~/.config/ccresu/config.yaml with ccresu config init, then edit it. The installers write it for you already.
  2. Run ccresu config validate to check the file, the environment overrides and every default.
  3. Run ccresu doctor to check the Claude Code CLI, transcript access, the database and the data directory.
  4. Start the watchdog with ccresu daemon, or install it as a service (see Deployment).

ccresu creates its SQLite database at ~/.local/share/ccresu/ccresu.db and, if the API is enabled, a bearer token with mode 0600 beside the configuration file in use (~/.config/ccresu/api-token for the default configuration). Neither is created until it is needed.

Requirements

  • Claude Code installed and logged in: discovery runs claude agents --json, so claude must be on PATH.
  • Read access to ~/.claude/projects and ~/.claude/session-env for transcript-based detection and verification.
  • No root privileges: everything lives under your home directory, and the installer refuses to run as root.
  • The raw scripts the two lines above pipe into a shell: https://raw.githubusercontent.com/jymchng/ccresu/main/scripts/install.sh and https://raw.githubusercontent.com/jymchng/ccresu/main/scripts/install.ps1.
