Deployment

Run ccresu as a user-level systemd service, or under any supervisor that can restart a process.

Download .md

ccresu is a long-running foreground process. It needs no privileges, writes only under your home directory, and handles SIGTERM by finishing its current step and releasing the database and the API port.

systemd (user unit)

The daemon needs your Claude Code credentials

Run the daemon as the user who owns ~/.claude. A system-wide unit running as another user, or as root, will not see the sessions it is supposed to recover.

Running the API

ccresu serve starts the REST + SSE API. It binds 127.0.0.1 unless the configuration says otherwise (:8787 is promoted to 127.0.0.1:8787, so a bare port cannot expose it by accident), and it writes a bearer token with mode 0600 on first start, beside the configuration file in use (~/.config/ccresu/api-token by default, /elsewhere/api-token with --config /elsewhere/config.yaml). Expose it beyond loopback only through a reverse proxy you control, and keep the token out of browser-visible code.

Upgrading

  1. Stop the daemon: systemctl --user stop ccresu.
  2. Download and verify the new release asset, replacing ~/.local/bin/ccresu.
  3. Run ccresu doctor to confirm the database schema and the Claude Code CLI are readable.
  4. Start the daemon again and check ccresu status.

The database is migrated forward automatically on start. Back up ~/.local/share/ccresu/ccresu.db before a downgrade, since older binaries reject a newer schema.

Other supervisors

  • macOS: a launchd LaunchAgent running the same ccresu daemon command.
  • Windows: a Task Scheduler task set to run at logon with ccresu daemon.
  • Containers: mount ~/.claude and the data directory as volumes, and run the daemon in the foreground; the SQLite driver is pure Go, so there is no libc dependency.
  • Supervisors that stop the process with SIGKILL skip the graceful shutdown; the state machine is crash-safe, so the next start reconciles the stale attempt.
