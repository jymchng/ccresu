Documentation

Everything ccresu does, in the order you need it: install it, configure it, learn the commands, understand the recovery state machine, then deploy and troubleshoot it. The same material ships in the repository under docs/.

Download .md
  • 01InstallationInstall a released binary with a single line, or build from source with Go 1.26 or newer.
  • 02Tutorial: your first recovered sessionThirteen steps from an empty machine to a session that was resumed for you, then the same state driven by hand and over the API.
  • 03ConfigurationOne YAML file, validated at startup, with environment variables that always win.
  • 04CLI referenceFourteen commands, five global flags, and exit codes a script can branch on.
  • 05How recovery worksFrom the limit banner to a verified resume, through an explicit persisted state machine.
  • 06Telegram notificationsOptional, deduplicated, off the recovery path: a Telegram outage can never block a resume.
  • 07DeploymentRun ccresu as a user-level systemd service, or under any supervisor that can restart a process.
  • 08SecurityLoopback-only API, a token for every write, no terminal automation and no telemetry.
  • 09TroubleshootingDiagnose with doctor, inspect and history, then match the symptom.
  • 10Known limitationsWhat ccresu deliberately does not do, and where it can still be defeated.

Release notes live on the releases page. Found something wrong in these docs? Open an issue.
