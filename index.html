Local-first watchdog for Claude Code

Your Claude Code session, resumed after the limit resets.

ccresu watches your sessions, recognises the usage-limit message, waits for the reset time in the right timezone, then resumes the same conversation with claude -p --resume — preserving history, working directory and active goal — and verifies the resume actually happened.

Built around the only thing that matters: the conversation continues

Eight behaviours, all implemented in the binary you install — no cloud service, no dashboard to deploy, no hidden agent in your editor.

  • Recognises the real limit message

    Normalises case, wrapping, ANSI colour codes and unicode punctuation before matching, so a wrapped or restyled banner still counts.

    Configurable patterns, per-match confidence, false-positive guards.

  • Waits for the actual reset time

    Parses “resets 12pm (Europe/Berlin)”, 24-hour clocks, relative durations, tomorrow and explicit dates, keeping the message's own timezone.

    IANA timezones, DST-safe, poll backoff when no reset time is given.

  • Resumes the same session

    Runs the documented claude -p --resume <session-id> with a continuation message. No forking, no new conversation, no keystroke injection.

    Conversation history, working directory and active goal are preserved.

  • Proves the resume happened

    A launch is not a recovery. ccresu verifies the session id is unchanged and the transcript grew before it records RESUMED.

    Verification timeout and health checks are configurable.

  • Survives restarts and reboots

    Every session, schedule, attempt and state transition is persisted in SQLite with WAL, so a restart continues where it stopped.

    Idempotent transitions, duplicate-recovery prevention, attempt history.

  • Tells you what happened

    Optional Telegram notifications for limit detected, waiting, recovery started, resumed, failed and session completed.

    HTML-escaped templates, deduplicated, queued off the recovery path.

  • Scriptable local API

    A REST API plus an SSE event stream on loopback, so a script or dashboard can follow sessions and trigger recovery.

    Bearer token for writes, Origin allowlist, rate limits, size limits.

  • Safe by default

    Binds 127.0.0.1, ships no web UI, never drives an interactive terminal and redacts secrets from logs and errors.

    Token file written 0600, constant-time comparison, no telemetry.

How it works

Five steps, each one observable from the CLI. Nothing happens silently: every step is a persisted state transition you can read back.

  1. 01

    Watch

    ccresu daemon

    Discovers Claude Code sessions from claude agents --json and from transcripts under ~/.claude/projects, then follows their output.

  2. 02

    Detect

    ccresu inspect <session-id>

    Matches a usage-limit banner and records a confidence-scored event. Auth errors, network failures and user cancellations are explicitly not limits.

  3. 03

    Schedule

    ccresu history <session-id>

    Resolves the reset time in its own timezone, persists it, and polls with exponential backoff when the message carries no time.

  4. 04

    Resume

    ccresu recover <session-id>

    After the reset, checks the session and the limit, then resumes with claude -p --resume in the original working directory.

  5. 05

    Verify

    ccresu status

    Confirms the same session id still exists with a longer transcript before recording RESUMED, and notifies you if Telegram is configured.

One binary, no dependencies

Install in one command

One line: it detects your platform, downloads that release asset, verifies it against the published checksums.txt, and put the binary on your PATH. The SQLite driver is pure Go, so there is nothing else to install.

  • Assets: ccresu_<version>_<os>_<arch>.tar.gz (.zip on Windows)
  • Targets: linux, darwin and windows on amd64 and arm64
  • Or build from source with Go 1.26: make build

What it will never do

  • No keystroke automation

    Resume runs as `claude -p --resume <session-id>` with the message as an argument. No pty, no simulated typing, no fork.

  • No limit bypass

    ccresu never tries to lift a quota. It reads the reset time from the message, waits for it, and acts only afterwards.

  • No hosted service

    State lives in a local SQLite file. The optional API binds 127.0.0.1 and the binary ships no web UI.
